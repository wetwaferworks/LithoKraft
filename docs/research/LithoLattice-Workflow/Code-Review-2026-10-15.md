## Etchor / Selector / lithography state
- **EtchOR block:** registered as `lithokraft:etchor` (content/blocks.cpp:139, append-only id 57, SimRole::EtchOR at the end of the enum in blocks.h:133). There's no .ltxr art yet. The behavior in content/components/etchor.cpp is describe-only and just returns the name.
- **Etch flow:** game/etching.cpp and etching.h. etchChip(inv, name) is atomic. It consumes 1 Wafer Silicon and produces 1 ChipOR with customName set to the name field (≤64 bytes, no control characters). It's reachable only through the `etch <name>` console command (game_commands.cpp:100-116 → game.cpp:180). The name persists in player.dat v5 (world_save.cpp:534, :659-680).
- **Gaps:** no in-world interaction or UI (the name field isn't built), no power or Laysor requirement, and no input from SelectORs. The output is always a generic ChipOR, and **no circuit or graph gets etched into the chip**: the chip carries only a name. ChipOR and the ChipOR Viewport exist (blocks.cpp:108, :113; chipor_viewport.cpp, circuit_scene.cpp), but nothing links them to etching.
- **SelectOR, ConnectOR, Laysor, AutoFabOR:** **don't exist in code.** They appear only in comments (etching.h:9, items.cpp:13, etchor.cpp header). "Selector" matches elsewhere are unrelated (procgen and AI selectors).
- **LithographOR:** its row is commented out (blocks.cpp:76) with a warning to re-add it only at the end of the list to keep save ids stable. There's no behavior.
- **Related existing blocks:** PortOR and Fusor (logic_components.cpp:344, :380) and Certificate Table (certificate_table.cpp, signing).
