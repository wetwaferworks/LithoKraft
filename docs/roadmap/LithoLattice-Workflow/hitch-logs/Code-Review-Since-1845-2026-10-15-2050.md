## Findings (severity ranked)

### HIGH
- **H1 FPS regression, not attributed.** Bench rt8 software at 20:41: walk 31.5 ms avg (p99 40.6), orbit 30.9/32.3 ms
  (p99 37-43). The 19:24 baseline was walk 44.9 FPS (~22 ms) and orbit 48.0 FPS (~21 ms). The A/B with foliage textures
  disabled was interrupted twice (windows), so foliage is the suspect but isn't proven. Machine load also changed:
  chrome and pythonw were busy. Action: A/B in the overnight tree.
- **H2 Foliage quad budget.** Shared meshes are 88-438 quads per instance (crystal_shrub 438, reeds 334, cattail
  320). The mesher caps a sub-chunk at 16384 quads and trims beyond that. The dense capture scene hit it
  ("sub-chunk has 17757 quads, trimmed"). Worldgen density (2-4% of columns) stays far below the cap, but a
  creative player filling a sub-chunk can trim geometry. Every instance pays full quads (no LOD). Action:
  coarser LOD for distant sub-chunks, merge coplanar micro-faces, cull faces against solid neighbours.

### MEDIUM
- **M1 Per-cell string lookups.** In the foliage meshCustom, every cell builds 11 "foliage_m<id>" strings and does
  11 map lookups. Cache them once per BlockMaterials.
- **M2 Asset/generator drift unchecked.** mesh() prefers the .lthm assets (baked LITHOKRAFT_MODELS_DIR source
  path) but never checks they still match buildModel(). Stale assets would silently diverge. In packaged
  builds the path is missing, so it falls back to the generator: fine, but a different code path from dev.
  Add a selftest: asset == generated.
- **M3 biome_capture --foliage writes into the source tree** (assets/models/foliage) on every run. Also, the first
  run caches mesh() before the assets exist (asset=0 for later kinds). Split this into an explicit
  --foliage-write-assets.
- **M4 Cattail 2-block overhang.** The upper half lives in the air cell above without owning it. Blocks or
  structures can be placed through it, raycast/pick hits only the lower cell, and sub-chunk-top culling can
  pop it. Now that foliage_3d runs before structures, a structure or tree can intersect a cattail head.
- **M5 Normal-mode mouse capture: code-verified only.** main.cpp only gates on `benchSeconds <= 0`. Normal mode is the
  unchanged pre-1925 logic (capture when the game wants it and the window is focused, re-applied when the OS
  drops it). Not live-tested, so as not to steal focus during JD's session.

### LOW
- L1 shrubs.h include in foliage.cpp is now unused (the bush became the Tron routing mound).
- L2 content_selftest litho check relaxed from `reg.size()==kVior+1` to `>=` (the foliage test owns the exact size).
- L3 `game/LithoKraft/saves/world/level.json` appeared in the source tree (a run with cwd = tree). Exclude it from packages.
- L4 Placeholder foliage textures foliage_m32-m42 sit in all 3 packs. CloudAtlas owns the real art.
- L5 Icons are small within their 128px frame (the model covers 4-9% of samples). Frame them tighter.
- L6 Etchor open items (unchanged): SelectOR role undefined; chip goes to the inventory, not out the front; chip
  code not stored on the item; wafers load only via etchload; beam glow is not seam-aware; Debug exe is older
  than the 19:24 main.cpp edits.
- L7 signal.cpp hsLampsBatch now keeps facing bits for directional lamps (sim change). The hash was unchanged
  then (aa82...), and the 8 litho wiring tests pass.
