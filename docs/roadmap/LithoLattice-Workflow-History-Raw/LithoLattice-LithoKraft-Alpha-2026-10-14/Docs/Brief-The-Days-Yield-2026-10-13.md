### What the review settled (root causes JD asked it to answer)

1. **The 4 save round-trip failures are NOT data loss — verified.** Diagnostic harnesses replayed the selftest scenarios exactly: all columns load, `importState` succeeds, signal export byte-identical, **0 voxel diffs, 0 state diffs**. The only difference is `VoxelPalette` *insertion order*; `sameCells` compared palettes by order + raw indices. The comparator was wrong; the data is semantically bit-perfect. (Side effect only: re-saved files are not byte-identical to originals.)
2. **The "no PBR material registry" gap is fixed in production.** Main always builds the registry → WorldSave registers MATS (string IDs, 256 cap); the selftest log line persists only because the selftest constructs WorldSave with `nullptr` materials.
3. **Protocol-version answer (H2, literal):** `knownProtocolVersions()` = **{1,2,3}** exists, but **no code installs it or constructs a ConnectHandshake at all**. The actual default offer is **{3} only** (empty config → ctor fills `{kProtocolVersion}` = V3); a v2-only peer is rejected fail-closed. Codecs: 2→V2Delta, 3→V3StableIds; **no v1 codec exists in-tree**. JD's decision is therefore really: {3}-only as-is, or install {1,2,3} *and* write the missing v1 codec path.
4. **Signing-key state — clean, with one operational fact.** Exhaustive sweep (every 64-hex literal in source/tests/game/tools + all three root snapshot zips, each derived as an Ed25519 seed and compared): **no private key material exists in the tree**, and no key material is reproduced in any review file. The baked key **is still the test key**, so release builds refuse to boot by design (game main only, `#ifdef NDEBUG`) until JD installs his real keypair. Historical git-history exposure can be neither confirmed nor cleared from this tree (no `.git` here); the key is correctly treated as retired regardless.
5. **ChipOR and scout selftest failures are both test bugs** — chipor's guard demands registry size 55 while legitimate appends (Structure Block, Certificate Table) make it 57 (all id-level checks pass); scout omits the ModelResolver that `dimensions.cpp` passes. The two cheapest "failures" on the board.
6. **Mesher sub-chunk failure is a test bug** (two reviewers converged independently): the check assumes the surface sub-chunk is the topmost; the mesher's own unit tests pass.

## 5. Timing Handshake / Time Serialization — state

**Sources:** `Timing-Handshake-Merge-2026-10-13.md`; `Pull-Tick-Prototype-2026-10-13.md`; `Time-Serialization-Workbench-2026-10-13.md`; `Time-Serialization-Control-Coupling-Addendum-2026-10-13.md`.

### The algorithm and its prototype verdict

The Timing Handshake (JD's design, dictated 2026-10-12/13) inverts the tick: **pull, don't push** — pull threads run an infinite polling loop asking the authority *"can I tick? is it time to tick?"*; the main game thread is the sole authority opening tick windows in fixed order; synchronization is two synchronized high-resolution-counter reads (Windows QPC; Linux prototype equivalent `std::chrono::steady_clock` / `CLOCK_MONOTONIC`), one from the pull and one from the push, both reading the same counter. Four phases per cycle (tick, tock, tick, tock), tunable — tested at 4, 8, and 16 phases/cycle. After firing, each pull thread pushes results and waits: no thread may pull phase N+1 until every thread has pushed phase N and the authority has committed. **Scope boundary (JD, hard rule): the handshake applies only to the deterministic circuit systems — Trace and Signal inside the game, and core sim timing ("our GPS"). Mobs/entities must NOT use it** — *"otherwise they run at 512 and the bones break"*; they need their own independent ticking system (the prototype's free-run pool models non-critical *engine* systems only).

Prototype results (isolated tree, production untouched, manifest identical before/after):

- **Determinism 24/24 PASS** — pull model reproduces the sequential outcome and logical firing sequence exactly at every thread count (1/2/4) and every phase count (4/8/16), sizes 64 / 512 / 4,096 components. Determinism is a property of the protocol (**phase-boundary state visibility**: snapshot reads, pending writes, commit at the barrier), not of the schedule. Phase protocol: barrier-order violations 0; QPC-agreement violations 0 across 10,000 phases × 4 threads.
- **Performance, honestly:** on the 2-core VM with lightweight stub components the handshake is **not faster** than the dispatch loop (~2.5 µs/phase protocol floor at small scale; parity only with heavy per-fire work — heavy spot check 0.74× → 0.99× → 1.05× as threads grow). Its wins are structural: sync cost scales with thread count, not component count; cadence phases generalize clock domains; free-run systems are actually free (225,892,096 evaluations alongside a deterministic run, hashes unchanged). The win for LithoKraft's real heavy loads (signal propagation, 512 Hz chip domains) is **projected, not measured** — this VM cannot measure it fairly.
- **Missed-window policy — deadline-skip TESTED, FAILS:** an authority that closes a phase after a 50 µs deadline and commits without late threads **diverged from the sequential outcome hash**. There is no cheap skip with this protocol.
- **Decisions on the open questions (JD delegated the calls; confirmed 2026-10-13 00:12 EDT):** (1) **Missed-window policy: WAIT** — an overrun extends the phase; the overrun is logged and counted, repeat offenders flagged; deadline-skip rejected. (2) **Hung-component watchdog: FREEZE** — past a hard ceiling, freeze the sim clock (tick_freeze semantics) and raise a fatal diagnostic naming the component; never force-advance. A frozen world can be saved, inspected, recovered; a force-advanced world is corruption. World permanence outranks frame rate. Straggler cost is structural: one 3 ms component moved its phase from 0.021 ms median to 3.014 ms — tail latency *is* the worst component, every phase, by construction; outcome stayed bit-identical.

### 6a. Control serialization — one serialized stream for ALL control sources

**Source:** `Control-Serialization-2026-10-13.md`. Tree: `~/workspace/experiments/control-serialization/`. JD's spec (12:44–12:46 EDT): hook the control system up just like the Timing Handshake, process it before and after, so key presses are *"in line and serialized with the timing handshake and very very responsive"* — at **the single power of two** only.

**What was built:** one serialized input stream for **ALL control sources (keyboard/mouse/gamepad + IPlayerController/MCP agents)**, carried in new `engine/src/sim/control_stream.h/.cpp`, owned by SimThread and exposed as `SimThread::controlStream()`.

- **Events** are `{seq, tick, source, sourceId, kind, payload}`; kinds: `Edit`, `Ray` (aim), `PlayerChunk`, `Locomotion`, `ControlFrame` (mirrors `mcp::IPlayerController::ControlFrame` field-for-field; the adapter is game-side so the sim library does not depend on the mcp library). Sources: `Local`, `McpPilot`, `Script`, `Replay`, `Test` — recorded verbatim so a demo record shows every source that drove the world.
- **The stamp domain is the sim's own accounting:** `tick` is the world-tick index (the same counter keyed random streams and edit stamps use; in handshake mode it advances only at committed barriers). **The gear is the world tick itself** — world TPS is already restricted to 32/64/128/256/512. No sub-tick rates, no domain ladder for control.
- **PRE phase** (at phase boundary, inside the sim thread's mutation window): drain every producer's submissions plus pre-stamped injections; **stamp/enqueue** live events `(seq = nextSeq_++, tick = worldTickN_)` in drain order — the sim thread is the *single sequencing point*; merge into the pending buffer sorted by `(tick, seq)`. The handshake's group-2 (clock-domain) phase then runs, as before.
- **POST phase** (`applyControlEvents` at the world-tick step head): extract every event with `tick <= worldTickN_` in `(tick, seq)` order and **apply exactly-once, in stamp order** — Ray events move the *stamped aim*, PlayerChunk events move the *tick area*, Edit events run the unchanged edit application against the stamped aim (re-cast follows any world-changing edit and any Ray event, per-event, so stream order between a ray move and an edit is honoured exactly). Then `IWorldSimulation::tick` runs, inside which the handshake's group-1 (Signal) phases fire. In legacy mode the same PRE/POST bracket wraps the plain tick.
- **Why it was needed (the gaps closed):** previously SimThread quantized edits only; the aim ray lived in a triple-buffer slot read fresh at application time (the same edit stream could resolve differently across frame rates, and no record of the aim existed), and the player chunk — which defines the TickArea — was a bare atomic the frame thread could rewrite *mid-burst*, between two world ticks of one catch-up burst. Neither was sequence-numbered; nothing a demo system could have recorded existed.
- **Discipline:** exhaustive, exactly-once, in stamp order — **there is no code path that discards an event**. Late extractions (past-stamped injections only) are applied and counted in `lateApplied`; order regressions counted in `orderViolations`; `dropped` is 0 by construction (the field exists so tests and IDemoRecord can *assert* it). One deliberate behaviour tightening on the paused path: application is now stamp-driven instead of "apply everything now" — identical for live input; a replayed future-stamped event now correctly waits for its tick. Presentation-only consumers keep reading raw by doctrine (HUD look-at raycast, camera smoothing, game-thread locomotion stepping); sim-affecting consumers read only stamped state. Locomotion/ControlFrame events have no sim-thread consumer by design — they are first-class stream kinds *now* so the record format is complete; IDemoRecord records them at their game-side tap.
- **Routing inventory (nothing sim-affecting bypasses the stream):** local keyboard/mouse/gamepad via `InputSystem` → `Game::handleWorldActions` → `SimThread::edit()` (Edit, source Local); aim ray via `SimThread::setRay()` (called before `handleWorldActions` in the same frame, so a press and its aim are adjacent in stream order); player position → tick area via `setPlayerChunk()`; MCP pilots translate to synthetic InputEvents upstream and cross as Edit/Ray/PlayerChunk through the game's merged input (per-pilot *attribution* merges upstream today — the ControlFrame kind exists for the attributed wiring IDemoRecord will want; documented gap, not a bypass); in-world Keyboard-block typing and console/script commands cross as Edit/Command events.

### 6b. IDemoRecord — demo recording on the control stream

**Source:** `IDemoRecord-2026-10-13.md`. Same experiment tree (`~/workspace/experiments/control-serialization/`); production untouched, verified byte-identical against the fix-program final manifest at the end of the run. JD's directive 12:46 EDT ("the whole demo system"), built in the experiment tree first per JD's 14:24 EDT call.

**Interface** (new `engine/src/sim/include/litholattice/sim/idemo_record.h`; implementation `engine/src/sim/demo_record.cpp`): abstract **`IDemoRecord`** (`session()`, `lastError()`); **`DemoRecorder`** — `begin(ControlStream&, DemoSessionInfo)`, `pump()`, `finish(finalWorldHash, totalTicks)`, `abort()`, `bytes()`, `saveToFile(path)`; **`DemoPlayer`** — `load`/`loadFile`, `parsed()`, `submitInto(ControlStream&)`; free functions `parseDemo`, `summarizeDemo`, `demoEventsInTickRange`. **`DemoError` codes are distinct, never collapsed into a bool:** `None`, `Io`, `EmptyFile`, `BadMagic`, `UnsupportedVersion`, `SegmentBadMagic`, `SegmentUnsupportedVersion`, `SegmentChecksum`, `SegmentMalformed`, `HeaderMismatch`, `TrailerBadMagic`, `TrailerChecksum`, `TrailerCountMismatch`, `State`.

**Passive-tap rule:** the recorder is passive by construction — its only stream operations are `setRecording(true/false)` and `takeRecord()` on the tap the control layer already provided. It never submits, never extracts, never stamps. `finish()` does a final pump, appends the trailer, detaches; `abort()` detaches *without* a trailer — the deliberate crash image. Session identity (`DemoSessionInfo`) pins world seed, mode, tick rate (the gear), handshake phases, stream format version (LLCS = 1) and demo format version (= 1); the §3 proofs used worldSeed = 0 (the scenario builder's Wafer worldgen is pinned to seed 0 — documented in the test code).

**Container format — LLDM v1** (little-endian): `[ 8-byte preamble ][ segment frame ] × N [ 40-byte trailer — clean finish only ]`. Preamble: `LLDM` + u16 demo format version + u16 reserved. Each frame is `u32 payloadLen` + **one complete LLCS v1 stream** (that segment's events; declaredTicks = 0 — ticks are a whole-session figure). **Trailer `LLDT`** carries u16 version, **u64 final world hash**, u64 total events, u64 total ticks, and a **u64 FNV-1a checksum over the whole record — precisely, over all bytes preceding the trailer** (via `DeterministicScheduler::hashBytes`), stored at trailer+32 (file offset size−8). Deliberate deltas from a monolithic LLCS stream: framed segments make the file **incrementally appendable** (a running session lands a complete, valid segment every pump — a crash loses at most the unpumped events) and make **torn-tail recovery** possible; the trailer carries the *outcome* (final hash checkable against any replay without re-running it), cross-checked against the segments' declared counts and the recovered count (any disagreement = `TrailerCountMismatch`). Two judgment calls recorded: trailer version mismatch reports as `UnsupportedVersion` (no trailer-specific code invented mid-build); salvaged-segment events are returned for replay but do **not** increment `segmentsRecovered` nor enter the certified count sum — salvage widens what you can *replay*, not what you can *certify*.

**Phase 1 — Model dithering (near-camera screen-door fade).** Geometry whose view depth falls inside the band **[near, far]** (default 2..8 blocks) is discarded per-pixel against a deterministic threshold; closer than `near` fully faded, beyond `far` untouched. **Keyed to the active camera** — the discard uses the rendering view's own depth, so free cams, **MCP/agent cameras**, and Daemon-vision feeds are no longer swallowed by a wall of voxels. Pattern: **interleaved gradient noise (Jimenez 2014)** — a hash of integer pixel position only; no frame counter, no time, no per-object seed, so a static camera is bit-stable across frames and the CPU and GLSL forms agree pixel-for-pixel on the discard decision. Implementation is a **shading-stage seam** (test runs from the fragment's view depth; no remeshing): software renderer classifies per-triangle (fully-in triangles dropped before rasterizing — faded geometry costs nothing; straddling triangles test per-pixel before shading and before any depth write, i.e. true discard semantics; blended sprites fade as whole billboards by nearest-corner distance; HUD/lines never faded); GL33 via a guarded block in shared `chunk_shading.glsl` + inline twin in `chunk_pbr.frag`; Vulkan **not plumbed** (no push-constant/descriptor path for the band uniforms yet — the interface default is an honest no-op, documented in `renderer.h`, never a fake). **Cvars: `render.model_dither` (default-ON at the setting level, applied by the game at startup and live on change — JD's "standard feature and staple" call), `render.model_dither_near` = 2, `render.model_dither_far` = 8**, driven through `IRenderer::setModelDither(enabled, near, far)`. One defect found and fixed during completion: defaulting the renderer-*class* member ON broke 6 existing `engine_render` checks (headless quads at clip-w 1 rasterized nothing) — the *setting* defaults on and the game applies it; the *class* starts off like all other renderer state. Verification: rasterizer mid-band coverage 2535/7600 ≈ 33% at fade = 1/3 (matches theory); fade endpoints/midpoint exact; close-up 720p cost off 57.27 ms → on **55.22 ms** (faded triangles skip rasterization); the lab close-up capture is a stress shot (camera embedded in geometry at the seeded spawn), not a beauty shot — the ON frame visibly un-swallows the camera while everything beyond the band stays solid; at ~65 blocks the spires frames agree, as designed.

**Phase 2 — Software AA suite as selectable named modes.** `render.aa` = **`off | fxaa | cmaa | ssaa2x`**, runtime-switchable with no restart, applied on the finished world frame after sprites and **before overlays/HUD — HUD is never AA'd** (in `ssaa2x`, renderFrame rasterizes the world at 2× and resolves before the overlay stage). **Default: off** — JD reviews the capture sets and picks the shipped default himself; nothing pre-empts that call. The flagship result deserves its line plainly: **clean-room CMAA-lineage coverage restoration measured CHEAPER than FXAA on CPU — 720p post 14.1 ms vs 27.8 ms; 1080p 32.5 ms vs 71.8 ms — while touching only 2.88% of pixels vs FXAA's 8.25%.** Mechanism: edge detection on luma steps *and* depth-buffer steps with CMAA2 conservatism (a monotone luma ramp is a texture gradient, not a geometry edge, and is rejected unless the depth buffer vouches for a geometry step — thin trace lines and texture detail survive); each edge run's coverage is integrated **analytically** from the reconstructed subpixel offset (no lookup textures); an exactly axis-aligned edge has exact 0/1 coverage and blends **nothing** (dedicated engine check). **Phase 3 — ASCII + Systerian renderers (glyph-grid post stage).** A post stage on the software renderer's finished frame (`software_ascii.{h,cpp}`): the frame is summarized into cells (~1:2 character aspect); each cell's average luminance selects a ramp level, its average colour tints the glyph. Outputs: **a `.txt` grid + a PNG** visualization (hand-built 5×7 bitmap font for the ASCII set, no external font dependency). **Cvars: `render.ascii` (bool, default off), `render.ascii_cols` (40..400, default 160), `render.ascii_set` (`ascii` | `systerian`, default `ascii`)**, applied live through `IRenderer::setAsciiMode` / `setAsciiGlyphSet`; the stage runs after AA and before overlays/HUD, and the raw text grid is retained on the renderer (`asciiText()`) for machine consumers.

**The Systerian map was FOUND in the tree — never invented.** JD's reference ("the map that we have for the ASCII-to-Systerian map") exists exactly where his materials said: **`engine/src/systerian` — `isysterian.h`** (`engine/src/systerian/include/litholattice/systerian/isysterian.h`), the engine's certificate-signing script standard. Its ASCII layer, in the header's own words: a printable ASCII char (32..126) maps to **the glyph of its own code point** (`'A' = 65 → glyph 65`) — `valueForAscii()`. Systerian is a Cistercian-style numeral script: a value 0..9999 is ONE glyph (vertical stave + digit strokes by decimal place, rivet dots at every graph vertex — JD's rivet rule), and the codec is **generative** — `composedGlyph(value)` derives the full stroke geometry from the 9 unit strokes + place transforms, so real glyph artwork exists in the tree with no asset files. The Systerian renderer draws from that geometry directly (stave and digit strokes plotted into the cell, rivet dots at the vertices, tinted by cell colour). The codec's own ctest (`engine_systerian`, passing) verifies it against JD's reference generator masters, including `'A' → 65` and `' ' → 32`. The resulting ramp: `' '→32 '.'→46 ':'→58 '-'→45 '='→61 '+'→43 '*'→42 '#'→35 '%'→37 '@'→64` — note the darkest cell is *not* blank in Systerian mode (value 32 is a real glyph), which is faithful to the map and is what makes the mode read as a script. Systerian's text form is the **glyph-value grid** (each cell as its two-digit code-point value, fixed width, machine-parseable) — values are the script's native encoding; the value-grid mapping is engine-check exact (mid-gray → `58`, white → `64`).
