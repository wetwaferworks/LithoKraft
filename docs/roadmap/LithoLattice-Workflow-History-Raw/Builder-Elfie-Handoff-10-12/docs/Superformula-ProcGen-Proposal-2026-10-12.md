## 2. The math (clean-room source: the definition, nothing else)

**2D superformula** — radius as a function of angle:
`r(φ) = (|cos(m·φ/4)/a|^n2 + |sin(m·φ/4)/b|^n3|)^(−1/n1)`

**3D via spherical product** of two superformulas r1(θ), r2(φ):
`x = r1(θ)·cosθ · r2(φ)·cosφ`
`y = r1(θ)·sinθ · r2(φ)·cosφ`
`z = r2(φ)·sinφ`
θ ∈ [−π, π] (longitude), φ ∈ [−π/2, π/2] (latitude).

**Closed-form test anchor:** a=b=1, m=4, n1=n2=n3=2 → r(φ)=1 for all φ (unit circle).
Any implementation must reproduce this exactly (within float epsilon).

## 3. Architecture

New code lives in `engine/src/procgen/` (clean-room files, e.g. `superformula.h/.cpp`):

1. **Core sampler** — 2D `superR(phi, params)`, 3D `superPoint(theta, phi, params12)` returning
xyz. Pure functions, no engine dependencies. Parameter struct `{a, b, m, n1, n2, n3}` × 2
(one per spherical-product factor) + our extensions (per-angle modulation hooks).
2. **Voxelizer** — samples the parametric surface on an adaptive grid, fills the interior
(parity/winding fill on the sampled shell), and emits filled micro-cells into the
`SparseOctree` (subdiv module, up to 64³) → `.lthm` via the existing `ModelBuilder` /
`saveModel` path. Resolution is a parameter, not a constant.
3. **Preset gallery** — named parameter sets (our own tuning): starfish, shell, blossom,
rounded-cube, rotor, pod, … Each preset records its parameters + a thumbnail render.
Gallery lives as data (JSON) + a generator, so artists/JD can add shapes without code.
4. **ProcGen integration** *(proposed, pending lock — §5)* — a new node type (e.g.
`"supershape"`) in the procgen node graph, so worldgen JSON can place superformula
structures; plus an `author_models`-style CLI to bake presets to `assets/models/`.

## 4. Our tweaks (the "not Genicap's" part)

- Voxel-native from the start: we never mesh the analytic surface — we sample, fill, and emit
micro-cells. The subdivision mesher (BinaryQuad/MicroQuad LOD) renders them.
- Parameter modulation: a/b/m/n1/n2/n3 may vary as functions of θ/φ (e.g. twist a starfish
along its axis) — shapes the original formulation doesn't directly produce.
- Integer-grid snapping options for block-scale (not just micro-cell) generation.
- Everything downstream (octree, `.lthm`, mesher) is already ours.
